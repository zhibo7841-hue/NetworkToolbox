## RC remediation — Task 033-B

Remediation date: 2026-08-29

- **Lint:** Resolved. `core:network` now declares the existing
  `ACCESS_NETWORK_STATE` permission required by its own ConnectivityManager
  calls. This is a library Manifest contract, not a broad suppression; no new
  effective application permission was added.
- **Local-data backup policy:** Resolved. The application now sets
  `android:allowBackup="false"`. No `dataExtractionRules` or
  `fullBackupContent` rule existed, so no conflicting backup rule remains.
  README now states that network diagnostic data is not uploaded and app-local
  data does not participate in system cloud backup by default.

  legacy History summaries, Ping/TCP error labels, LAN range rejections, and

  CHANGELOG has an Unreleased section; RELEASE_PLAN and LAN Scanner design
  state their implemented status while preserving historical design context.
- **Verification:** `test`, `lint`, `assembleDebug`, and `assembleRelease` all
  pass locally. The Release APK is verified with APK Signature Scheme v2.

The version intentionally remains `0.1.0` / `1`, and no tag, release, upload,
or push was created. Those release-execution steps remain reserved for Task
034.

### Backup policy requiring a release decision

The application manifest currently sets android:allowBackup=true without a documented exclusion for the Room History database. Android system backup can include app data depending on a user's device and backup settings. Therefore, the public statement that all test results stay on-device cannot be guaranteed without an explicit backup policy. See P1-2.

## Findings and release gates

### P0 — release blockers

None found.

### P1 — resolve before public v0.2.0 release

1. **Make lint clean.** Resolve the seven MissingPermission errors in core:network with an accurate module-level permission contract and/or permission annotations, then run lint again.
2. **Decide and enforce local-history backup policy.** Disable Android backup for diagnostic history or explicitly exclude it, then align privacy wording. Do not claim on-device-only storage if platform backup can export it.
3. **Prepare public v0.2 release metadata and documents.** In an approved release task, set v0.2 versioning; update README features/install information; draft the changelog; reconcile RELEASE_PLAN and LAN scanner design; and push the three local commits for remote CI.
4. **Finish Chinese user-facing fallback text.** Localize LAN validation and History fallback/legacy summaries; avoid raw internal English strings.
5. **Run final device regression after P1 fixes.** Verify Home, Ping, DNS, TCP, Diagnostic, History, auto/custom LAN scan, cancellation, network change, cellular, VPN, and dual-stack Wi-Fi on Sony Xperia 1 VII / Android 16.

### P2 — address before or soon after release

1. Replace the OSS research placeholder with evidence-backed review if a new external library is considered.
2. Extend CI to run lint after P1-1 is fixed. Consider protected signed-release verification using repository secrets rather than local signing material.
3. Make History persistence failure observable to the user or a safe local diagnostic path. The recorder avoids failing a completed check when persistence fails, but this can hide a missing record.
4. Refresh screenshots against the actual v0.2 release candidate after final UI text is settled.

### P3 — post-release improvements

1. Add an SBOM/transitive-license review step to the release checklist.
2. Consider a Kotlin formatting/static-analysis gate after it can be introduced without release churn.
3. Keep mDNS, UPnP, MAC/OUI, device details, Wake-on-LAN, and IPv6 LAN discovery as separately designed future work.

## Required release sequence

1. Resolve every P1 item and rerun test, lint, Debug build, and Release build.
2. Push candidate commits and confirm remote CI on the same commit.
3. Build a fresh signed v0.2 release APK and re-verify package, version, SDK, and signature.
4. Perform and record final Sony Xperia 1 VII / Android 16 regression results.
5. Obtain maintainer approval before creating a v0.2.0 tag, GitHub Release, or uploading an APK.
