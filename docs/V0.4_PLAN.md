# NetworkToolbox v0.4.0 Plan

> Status: Planning
>
> Version: v0.4.0

## Release Goal

NetworkToolbox v0.4.0 will strengthen the product's core value: turning local
network observations and focused test results into cautious explanations,
possible causes, actionable suggestions, and a readable diagnostic report.

The release has two confirmed workstreams:

- **Automatic Diagnostics Phase 2:** a progressive, evidence-driven diagnostic
  flow that reuses existing Network Information, Ping, DNS, TCP, and conditional
  Traceroute capabilities.
- **Diagnostic Report Phase 1:** one complete in-app report with a general-user
  summary followed by bounded technical details, text copy, local PDF saving,
  and PDF sharing through Android platform APIs.

The product remains local-first. Network tests may contact their selected
network targets, but the diagnostic report and local network data are not
uploaded to a NetworkToolbox server.

## Confirmed Scope

### Automatic Diagnostics Phase 2

- Progressive checks for network state, IP configuration, gateway/local exit,
  Internet connectivity, DNS, and an explicitly selected target when relevant.
- Evidence aggregation with deterministic, unit-testable rules.
- Conservative findings with severity and confidence separated from raw check
  status.
- Possible causes and a short prioritized recommendation list.
- Retry/verify flow that reports whether a previous observation is still seen;
  it must not claim that the app repaired the network.
- Network-change detection that prevents results from different active networks
  being presented as one strong conclusion.
- VPN and Fake-IP as context or notice signals, not automatic faults.

### Diagnostic Report Phase 1

- One complete in-app report with a readable summary and expandable technical
  details.
- Copy as text, local Save PDF, and Share PDF after an explicit user action.
- Versioned, bounded report content with privacy-sensitive fields clearly
  identified.

## Explicit Non-Goals

- Automatic repair or Android network reset.
- Cloud AI diagnosis, account, cloud sync, or report upload.
- Online report URL, QR report, or cloud-hosted report.
- Automatic full `/24` LAN scanning during a normal Internet diagnosis.
- Wi-Fi Analyzer, Wake-on-LAN, SSL/TLS inspection, WHOIS, iPerf, IPv6
  Traceroute, Traceroute History, MAC/OUI, ASN, GeoIP, MTR, or unrelated tools.
- A definitive router, ISP, DNS-provider, or website-outage assertion from one
  probe.

## Delivery Baseline

The detailed product, evidence, rule, privacy, and technical baseline is
`docs/AUTOMATIC_DIAGNOSTICS_V2_DESIGN.md`. Implementation must be split into
independently testable tasks and must preserve the existing Ping/DNS/TCP/LAN
Scanner safety semantics.

## Task 054 Status

- Diagnostic retry/verification: **Completed**.
- A pure Kotlin comparator compares only stable `DiagnosticFindingCode` values
  after both runs complete, the target is compatible, the network fingerprint
  matches, and the required stage evidence is verified. It reports resolved or
  not reproduced, still present, new findings, unchanged, inconclusive, and
  changed-context outcomes without claiming that the app repaired anything.
- Boundary notices such as VPN, Fake-IP, and a non-responsive gateway remain
  contextual information rather than material problems. The current Analyzer
  remains the source of the current report severity and recommendations.
- Re-running from a completed live report keeps the previous result in the
  session, runs the normal diagnostic flow, compares the new completed result,
  and records the current run as one independent local history record. No Room
  schema or report snapshot format was changed; history-based comparison is
  intentionally not persisted as a relationship.
- v0.4.0 remains in Planning; this status does not authorize a release.

## Task 054-A Status

- Retry/verify no-active-network priority fix: **Completed**.
