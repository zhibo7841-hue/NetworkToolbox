# NetworkToolbox v0.3.0

NetworkToolbox v0.3.0 adds evidence-based LAN device identification and a
standalone IPv4 Traceroute tool while keeping all results local to the device.

## Highlights

### LAN Device Identification

- Enrich discovered LAN devices with Reverse DNS hostnames when available.
- Observe mDNS / Bonjour names and basic services.
- Read bounded SSDP / UPnP device descriptions when openly advertised.
- Display source-labelled hostname, manufacturer, model, and service details
  when the device provides them.

### IPv4 Traceroute

- Trace an IPv4 domain or address hop by hop.
- Show up to three probe results and latency details for each hop.
- Stop a trace and keep the hops already observed.
- Represent reached, partial, cancelled, failed, and network-changed states
  explicitly.
- Use an app-owned UDP Error Queue implementation without Root, SOCK_RAW, or a
  system traceroute command.

## Improvements and fixes

- Improved LAN Scanner device presentation and identity aggregation.
- Improved Traceroute timeout, partial-response, Fake-IP, cancellation, and
  hop-list explanations.
- Fixed Android 16 mDNS late-callback crashes.
- Improved UPnP Description HTTP/XML compatibility and safety handling.

## Requirements

- Android 12 (API 31) or later.

## Privacy

- No account required.
- No ads.
- Network diagnostic data, LAN observations, and History remain local.
- No network inventory or diagnostic report is uploaded.

## Current limitations

- Traceroute currently supports IPv4 only.
- Not every device exposes a hostname, manufacturer, model, or service data.
- Some intermediate routers may not respond to Traceroute probes; this does
  not by itself indicate a network fault.
